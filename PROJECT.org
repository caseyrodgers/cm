Build *11* (=cm_re/apps/tutor/src/buildNumber.ts=).

This repo (=github.com/caseyrodgers/cm=, branch =main=) holds two
things:

1. The *legacy app* (=cm=) — a ~2015-era GWT 2.7 / GXT 3.1 webapp,
   builds + runs locally on pinned JDK 8, otherwise set aside.
2. The *rewrite* (=cm_re/=) — a React + TypeScript PWA tutor plus a
   Java backend, in active development.

All design notes, investigations, and decision logs live in =*.org=
files at the repo root (plus a couple under =cm_re/=). This file is
the map. Every link is =[[file:…]]= — open in Emacs or follow the
path.

* Rewrite — subsystem notes

- [[file:SOLUTION_INFO.org][SOLUTION_INFO.org]] — everything about the *legacy solution content
  format* and the pre-processor that converts it: the real exported
  shape, malformed-authoring-tool patterns, the image taxonomy
  (WIRIS equation dupes vs. real inline math vs. diagrams vs. the
  shared specialchars set) and the reference-based image-copy fix,
  multiple-choice question extraction, and the regression bugs found
  running it at corpus scale.
- [[file:SOLUTION_DATA.org][SOLUTION_DATA.org]] — where solution data physically lives at each
  stage today, and the pipeline that moves it: legacy export ->
  LegacySolutionPreprocessor/ModuleAssembler (or live editor authoring)
  -> apps/tutor/public/modules/<subject>/bundle.json -> make dist ->
  deploy/web/ (committed to git) -> TutorServer -> browser IndexedDB.
  Sequence diagram included.
- [[file:AI_DISCUSS.org][AI_DISCUSS.org]] — the *"Learn" AI explanation* feature: three
  candidate serving models (bake into the module / server endpoint +
  client cache / hybrid), cross-cutting concerns (prompt-version
  keying, staleness, generation tooling), and a dated status log of
  what's actually built (live per-call today: grade-aware, MathML
  output, image/vision context for image-only problems, and follow-up
  questions on an explanation). The pre-generated-vs-live decision is
  still open.
- [[file:TUTOR_WIDGET.org][TUTOR_WIDGET.org]] — the *widget-slot infrastructure*: how a dead
  =tutor_widget_dummy.png= reference led to it, the plain-JS widget
  contract (=WidgetModule= / =WidgetContext= / =WidgetInstance=), the
  registry + React bridge, =Solution.widgetSlot= as a
  preprocessor-extracted field, the first =inputWidget=, and the
  open questions (wiring, grading, whiteboard conversion).
- [[file:SOLUTION_EDITOR.org][SOLUTION_EDITOR.org]] — the *solution editor* (=apps/editor=), the
  online-only TipTap authoring tool that replaces the legacy GWT
  =solution_editor=. Real now, through 2026-10-14: browse/search,
  create a new solution, and edit statement/MC question/steps against
  a file-backed CRUD API. Content preservation guards for MathML
  (=MathNode=), images (=Image=), and =<div>= elements (=DivBlock=)
  prevent TipTap from silently destroying markup it doesn't
  understand. A shared raw editor modal (split textarea + live
  preview + tag toolbar) replaced =window.prompt()= for all opaque
  node editing. Next up: MathEditor/KaTeX node, widget-slot + figures.
- [[file:GAMES.org][GAMES.org]] — *games, videos & resources* integration: the skill
  taxonomy (~468 fine-grained IDs), the game registry (4 local
  offline-capable games), the video registry (370 videos from 4
  legacy sources), fuzzy skill matching, the four surfaces (browse
  pages, score-screen suggestions, Resources toolbar button, game
  view related-subjects bar), routing, the per-game AI Explain
  button, postMessage protocol, and open items.
- [[file:IDEAS.org][IDEAS.org]] — running backlog of app-value ideas (tutor and
  editor both), each with a =DOIT= checkbox, a =Status:= line, and
  implementation notes once shipped. The working todo list day to
  day — check here first for "what's next."
- [[file:cm_re/DEBUG.org][cm_re/DEBUG.org]] — Eclipse debug setup for =apps/backend=: the
  local "Java Application" launch and the "attach 5005" remote launch
  against =make debug=, plus gotchas (=*.launch= is gitignored
  because Eclipse persists secrets into it).
