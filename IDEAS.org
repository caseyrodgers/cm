** Whiteboard Sketch AI
If there are graphics on the problem statement, the outline of the graphic should be part of the Sketch.

- [X] DOIT
Status: Done (2026-09-14)

Implementation notes: ~AiService.buildSkeleton~ (the "Sketch a starting
point" prompt) was text-only — unlike ~getAIForProblem~ and
~checkWork~, it never attached a problem's own images
(~store.problemImagesFor~), so a legacy problem whose figure is
authored as a picture rather than text gave the model nothing to draw
from. It now loads and attaches those images (vision) the same way
the other two endpoints do, and case (a) of the prompt (redraw a
geometric figure) explicitly tells the model to trace the actual
outline/proportions it sees in the image rather than substitute a
generic shape. No client-side change needed — the request is still
just ~GET /api/ai/skeleton/{pid}~; the server decides what to attach.

Verified: backend compiles clean (~mvn compile~); full e2e suite (37
specs, 1 pre-existing skip) still green — the two "Sketch a starting
point" specs mock the network route directly, so they exercise the
client contract, which is unchanged.

** Browse-only problems should be eligible for the missed-questions lesson
- [X] DOIT
Status: Done (2026-09-15)

Casey: "problems that are browse only should be included in generated
Test Lessons." ~makeMissedLesson~'s candidate pool required a scorable
MC question alongside having steps — an unnecessary exclusion carried
over from the practice-test picker's filter, since the lesson is a
pure walkthrough, never a re-quiz. Dropped the requirement; the pool
is now just "has steps," so a browse-only problem in the same chapter
(e.g. the 3 ~alg1ptests~ solutions with no choices in the source) is
legitimate remediation material and can now be picked.

Verified at the data level against the real bundle: before, all 3
browse-only-with-steps solutions were excluded from their chapter's
pool (49 candidates); after, all 3 included (52). Also found and fixed
a real e2e risk: ~missed-lesson.spec.ts~ assumed every lesson pid has
a question (no longer guaranteed) and had a genuine
~locator.boundingBox()~ race that doesn't auto-retry like ~expect()~
does. Full e2e suite green across repeated runs.

* Recommendation

Start with the struggling-problems queue + per-chapter mastery view —
both reuse data already being collected, need no new AI calls or
architecture, and turn "here are some stats" into "here's what to do
next." Text-to-speech is the best effort-to-value ratio for something
small and self-contained.
